# F1 數據說明文件

> 這份文件用最白話的方式，解釋每張 CSV 資料表裡每個欄位代表什麼意思。
> 適合完全沒接觸過 F1 數據的人閱讀。

---

## 什麼是 F1？快速背景

F1（一級方程式賽車）是全球最頂級的賽車比賽。每年有大約 24 場「大獎賽」（Grand Prix），分布在世界各地的賽道上。每場比賽週末通常包含：

- **FP1 / FP2 / FP3**（自由練習賽）— 讓車手熟悉賽道、測試車輛設定
- **Qualifying（排位賽）**— 決定正賽的起跑順序，跑最快的排第一（稱為「桿位 Pole Position」）
- **Race（正賽）**— 真正的比賽，繞賽道跑幾十圈，第一個衝線的就是冠軍

每條賽道會被分成 **3 個 Sector（分段）**，用來分析車手在不同路段的表現。

## 1. laps.csv — 圈速資料（最重要的一張表）

每一列代表「某位車手的某一圈」。如果一場比賽有 20 位車手，每人跑 53 圈，大約就有 1,000 多列。

| 欄位 | 中文 | 白話解釋 |
|------|------|----------|
| **Time** | 該圈結束的累積時間 | 從比賽開始到這一圈結束過了多久，格式是「天 時:分:秒」 |
| **Driver** | 車手代碼 | 三個英文字母的縮寫，例如 VER = Verstappen（乃哥），LEC = Leclerc，NOR = Norris |
| **DriverNumber** | 車號 | 每位車手的固定號碼，例如 1 號是 Verstappen，16 號是 Leclerc |
| **LapTime** | 圈速 | 跑完這一圈花了多少時間。這是最關鍵的數據 — 越短越快。例如 1:28.179 表示 1 分 28 秒 179 毫秒 |
| **LapNumber** | 圈數 | 這是第幾圈，從 1 開始 |
| **Stint** | 輪胎stint | 一組輪胎從裝上到換掉算一個 stint。例如 Stint 1 是第一組胎，進站換胎後變 Stint 2 |
| **PitOutTime** | 出站時間 | 如果這一圈是從維修站出來的，記錄出維修站的時間 |
| **PitInTime** | 進站時間 | 如果這一圈要進維修站換胎，記錄進站的時間 |
| **Sector1Time** | 第一段時間 | 賽道被分成 3 段，這是跑完第 1 段花的時間 |
| **Sector2Time** | 第二段時間 | 跑完第 2 段花的時間 |
| **Sector3Time** | 第三段時間 | 跑完第 3 段花的時間。三段加起來 ≈ 圈速 |
| **Sector1SessionTime** | S1 session 時間 | 跑完第 1 段時，距離 session 開始過了多久（絕對時間） |
| **Sector2SessionTime** | S2 session 時間 | 跑完第 2 段時的絕對時間 |
| **Sector3SessionTime** | S3 session 時間 | 跑完第 3 段時的絕對時間 |
| **SpeedI1** | 測速點 1 速度 | 在第 1 個測速點的車速（km/h） |
| **SpeedI2** | 測速點 2 速度 | 在第 2 個測速點的車速（km/h） |
| **SpeedFL** | 終點線速度 | 通過終點線時的車速（km/h） |
| **SpeedST** | 最高速 (Speed Trap) | 這一圈在大直線上測到的最高速度（km/h），Monza 通常超過 340 km/h |
| **IsPersonalBest** | 個人最快 | True = 這一圈是該車手目前為止的最快圈 |
| **Compound** | 胎種 | 用的是哪種輪胎。SOFT（軟胎，紅色，最快但磨最快）、MEDIUM（中性胎，黃色）、HARD（硬胎，白色，最慢但最耐用） |
| **TyreLife** | 輪胎使用圈數 | 這組輪胎已經跑了幾圈。數字越大，輪胎越舊、抓地力越差 |
| **FreshTyre** | 是否新胎 | True = 全新的輪胎（未使用過），False = 回收再用的舊胎 |
| **Team** | 車隊 | 所屬車隊名稱，例如 Ferrari、McLaren、Red Bull Racing |
| **LapStartTime** | 這圈開始的時間 | 開始跑這一圈的 session 時間 |
| **LapStartDate** | 這圈開始的日期時間 | 真實世界的日期與時間 |
| **TrackStatus** | 賽道狀態代碼 | 1 = 綠旗（正常比賽）、2 = 黃旗（前方有事故，需減速）、4 = 安全車、6 = 虛擬安全車（VSC） |
| **Position** | 目前排名 | 跑完這一圈時，這位車手排在第幾名 |
| **Deleted** | 圈速是否被刪除 | True = 這一圈因為違規被取消（例如排位賽超出賽道界限） |
| **DeletedReason** | 刪除原因 | 如果被刪除，說明原因（例如超出 Track Limits） |
| **FastF1Generated** | 是否自動生成 | True = 這筆資料是 FastF1 軟體自動補齊的，不是官方直接記錄的 |
| **IsAccurate** | 是否準確 | True = 這一圈的數據是可靠的。做分析時通常只用 IsAccurate = True 的圈，排除進出站圈、安全車圈等不正常的圈速 |

### 怎麼用？

- **比較兩位車手的速度**：篩選兩位車手，看每圈的 LapTime
- **分析輪胎衰退**：看同一位車手隨著 TyreLife 增加，LapTime 是否變慢
- **找最快圈**：排序 LapTime，最小的就是最快圈

## 2. results.csv — 比賽結果

每一列代表一位參賽車手的最終結果。一場比賽通常有 20 列。

| 欄位 | 中文 | 白話解釋 |
|------|------|----------|
| **DriverNumber** | 車號 | 車手的號碼 |
| **BroadcastName** | 轉播名稱 | 電視轉播上顯示的名字，例如 "C LECLERC" |
| **Abbreviation** | 車手代碼 | 三字母縮寫，如 LEC、VER、NOR |
| **DriverId** | 車手 ID | 系統內部識別碼，如 "leclerc" |
| **TeamName** | 車隊名稱 | 例如 Ferrari、McLaren |
| **TeamColor** | 車隊顏色代碼 | 16 進制色碼，例如 Ferrari 的 E80020（紅色） |
| **TeamId** | 車隊 ID | 系統內部識別碼 |
| **FirstName** | 名 | 例如 Charles |
| **LastName** | 姓 | 例如 Leclerc |
| **FullName** | 全名 | 例如 Charles Leclerc |
| **HeadshotUrl** | 大頭照網址 | 車手照片的連結 |
| **CountryCode** | 國籍代碼 | 例如 MON = 摩納哥，NED = 荷蘭 |
| **Position** | 最終排名 | 這場比賽最終排在第幾名。1 = 冠軍 |
| **ClassifiedPosition** | 官方認定排名 | 有些車手雖然沒跑完，但跑了足夠多的圈數仍會被分類排名 |
| **GridPosition** | 起跑位置 | 排位賽決定的起跑格位。1 = 桿位（最前面） |
| **Q1 / Q2 / Q3** | 排位賽各階段最快圈 | 排位賽分三階段淘汰，Q3 是最快的 10 位車手爭桿位 |
| **Time** | 完賽時間 | 冠軍的總時間，其他車手顯示與冠軍的差距 |
| **Status** | 完賽狀態 | "Finished" = 正常完賽，其他可能是 "Retired"（退賽）、"+1 Lap"（落後一圈） |
| **Points** | 積分 | 這場比賽拿到的積分。第 1 名 25 分、第 2 名 18 分、第 3 名 15 分...第 10 名 1 分，第 11 名之後 0 分 |
| **Laps** | 完成圈數 | 這位車手總共跑了幾圈 |

### 怎麼用？

- **看比賽結果排名**：用 Position 排序
- **分析起跑得失位**：比較 GridPosition 和 Position 的差距，正值 = 進步了
- **追蹤車手積分**：累加 Points 就是賽季積分

## 3. weather.csv — 天氣資料

每隔一段時間記錄一次賽道上的天氣狀況。天氣會直接影響輪胎策略和車速。

| 欄位 | 中文 | 白話解釋 |
|------|------|----------|
| **Time** | 時間 | 距離 session 開始過了多久 |
| **AirTemp** | 氣溫 | 空氣溫度（°C） |
| **Humidity** | 濕度 | 空氣濕度（%）。越高越潮濕 |
| **Pressure** | 氣壓 | 大氣壓力（hPa / mbar）。氣壓影響空氣密度，進而影響引擎和空力表現 |
| **Rainfall** | 是否下雨 | True = 正在下雨，False = 沒有下雨。下雨時需要換雨胎 |
| **TrackTemp** | 賽道溫度 | 路面的實際溫度（°C）。通常比氣溫高很多（太陽曬的），直接影響輪胎抓地力和衰退速度 |
| **WindDirection** | 風向 | 風吹來的角度（0-360 度，0 = 正北） |
| **WindSpeed** | 風速 | 風有多大（m/s）。大風會影響高速直線和煞車穩定性 |

### 怎麼用？

- **分析溫度對圈速的影響**：TrackTemp 越高，輪胎通常衰退越快
- **雨戰分析**：Rainfall = True 的時段，圈速會明顯變慢

## 4. telemetry_VER.csv — 車輛遙測資料（VER 最快圈）

這是最細緻的數據 — 記錄車輛在一圈當中**每個瞬間**的狀態。可以想像成一台超精密的行車記錄器，一秒記錄好幾次。

| 欄位 | 中文 | 白話解釋 |
|------|------|----------|
| **Date** | 日期時間 | 真實世界的精確時間，精準到毫秒 |
| **SessionTime** | session 時間 | 距離 session 開始過了多久 |
| **DriverAhead** | 前方車手 | 正前方的車手代碼。如果是空的，表示前面沒有車（或太遠） |
| **DistanceToDriverAhead** | 與前車距離 | 跟前面那台車相距多少公尺 |
| **Time** | 圈內時間 | 這一圈已經跑了多久（從這圈起點開始計算） |
| **RPM** | 引擎轉速 | 引擎每分鐘轉幾圈。F1 引擎最高約 15,000 RPM，數字越大代表引擎轉越快 |
| **Speed** | 車速 | 當下的即時車速（km/h）。Monza 大直線可超過 340 km/h |
| **nGear** | 檔位 | 目前在幾檔。F1 有 8 個前進檔（1-8），大直線用 8 檔，急彎用 1-2 檔 |
| **Throttle** | 油門開度 | 油門踩了多少（0-100%）。100 = 全油門，0 = 完全放開 |
| **Brake** | 煞車 | 是否在踩煞車。True = 正在煞車，False = 沒有煞車 |
| **DRS** | DRS 狀態 | 0-14 的數值。DRS 是尾翼開啟系統，在大直線打開可降低風阻、增加尾速。通常 10-14 = 開啟，0 = 關閉 |
| **Source** | 資料來源 | "car" = 車上感測器直接回傳，"interpolation" = 軟體插值補齊的 |
| **Distance** | 距離 | 從這圈起點到目前位置的距離（公尺）。一圈 Monza 大約 5,800 公尺 |
| **RelativeDistance** | 相對距離 | 跑了全圈的百分比（0 到 1）。0.5 = 跑了半圈 |
| **Status** | 狀態 | "OnTrack" = 在賽道上正常行駛 |
| **X / Y / Z** | 車輛座標 | 車輛在賽道上的 3D 位置座標，可以用來畫賽道地圖 |

### 怎麼用？

- **速度軌跡**：畫 Distance vs Speed 的圖，可以看車手在每個彎角的進出速度
- **煞車點分析**：找 Brake 從 False 變成 True 的位置，就是煞車點
- **油門使用率**：計算 Throttle ≥ 95 的比例，就是全油門百分比
- **比較兩位車手**：疊兩位車手的 Speed 曲線在一起，可以看誰在哪段比較快

## 5. stints.csv — 輪胎 stint 資料

記錄每位車手每組輪胎的使用情況。比賽規定至少要用兩種不同胎種，所以每人至少有 2 個 stint。

| 欄位 | 中文 | 白話解釋 |
|------|------|----------|
| **meeting_key** | 比賽識別碼 | OpenF1 系統中這個比賽週末的 ID |
| **session_key** | session 識別碼 | OpenF1 系統中這個 session 的 ID |
| **stint_number** | stint 編號 | 第幾組輪胎（1, 2, 3...） |
| **driver_number** | 車號 | 車手號碼 |
| **lap_start** | 開始圈 | 這組輪胎從第幾圈開始使用 |
| **lap_end** | 結束圈 | 這組輪胎用到第幾圈（進站換掉或比賽結束） |
| **compound** | 胎種 | SOFT / MEDIUM / HARD / INTERMEDIATE（半雨胎）/ WET（全雨胎） |
| **tyre_age_at_start** | 起始胎齡 | 裝上時輪胎已經跑了幾圈。1 = 全新，大於 1 = 在之前的 session（如排位賽）已用過的舊胎 |

### 怎麼用？

- **策略比較**：看不同車手選了什麼胎、什麼時候進站
- **一停 vs 二停**：stint_number 最大值 = 2 表示一停策略，= 3 表示二停
- **計算 stint 長度**：lap_end - lap_start + 1 = 這組胎跑了幾圈

## 重要觀念補充

### 輪胎三兄弟

| 胎種 | 顏色 | 特性 |
|------|------|------|
| **SOFT** | 紅色 | 抓地力最好、單圈最快，但磨損最快（大概只能撐 15-20 圈） |
| **MEDIUM** | 黃色 | 中間值，平衡速度和耐久 |
| **HARD** | 白色 | 最耐用，可以撐 30-40 圈，但單圈速度最慢 |

想像成跑鞋：軟胎像釘鞋（抓地力強但不耐穿）、硬胎像慢跑鞋（耐穿但不夠快）。

### 什麼是輪胎衰退？

輪胎隨著使用圈數增加，橡膠會磨損、溫度管理變差，抓地力下降，圈速就會越來越慢。這個「越來越慢」的速率就是**衰退率（degradation rate）**，單位是「秒/圈」。

- 衰退率 0.05 秒/圈 = 很低，輪胎很耐用
- 衰退率 0.15 秒/圈 = 偏高，可能需要提早進站換胎

### DRS 是什麼？

DRS（Drag Reduction System）= 減阻系統。車手在大直線上如果距離前車不到 1 秒，可以打開後尾翼的板子，減少空氣阻力，讓尾速增加大約 10-15 km/h，方便超車。這是 F1 為了增加超車機會而設計的規則。

### IsAccurate 為什麼重要？

做數據分析時，一定要記得篩選 `IsAccurate = True`。因為不準確的圈包括：

- **Outlap（出站圈）**— 從維修站出來，還在暖胎，速度很慢
- **Inlap（進站圈）**— 準備進維修站，會刻意減速
- **安全車圈**— 全場跟在安全車後面慢速行駛
- **紅旗影響圈**— 比賽暫停

這些圈速都不能代表車手或賽車的真實表現。

## 未來可開發方向

基於本專案已擁有的數據資產（遙測、圈速、輪胎策略、天氣、排名、賽事控制等），以下是可進一步開發的產品與應用方向。

### 產品一：F1 即時數據儀表板（Web Dashboard）

**概念**：將現有的分析模組包裝成互動式網頁應用，讓用戶自行選擇年份、大獎賽、車手，即時產出視覺化圖表。

**使用的數據**：全部（遙測、圈速、輪胎、天氣、排名、積分）

**技術選型**：
- 快速原型：Streamlit / Dash（Python 生態，可直接調用現有模組）
- 進階版本：Next.js + Plotly.js / D3.js（前後端分離，效能更好）

**功能範例**：
- 任選兩位車手疊合遙測曲線（速度、油門、煞車）
- 輪胎策略時間軸，一眼看出誰一停、誰二停
- 賽季積分走勢互動圖，hover 顯示每站結果

**目標用戶**：F1 車迷、賽事分析師、體育媒體記者

### 產品二：賽事預測 AI 模型

**概念**：利用歷史數據訓練機器學習模型，預測比賽結果與策略。

**使用的數據**：圈速、輪胎衰退率、天氣、起跑位置、歷史成績

**可預測項目**：
- 比賽最終排名（分類模型）
- 最佳進站圈數（回歸模型，結合輪胎衰退率 + 安全車機率）
- 輪胎策略建議（一停 vs 二停的勝率分析）
- Fantasy F1 車手得分預測（幫用戶最大化 Fantasy 積分）

**延伸應用**：博彩分析工具（模型預測 vs 市場賠率的差異，尋找 value bet）

**技術選型**：scikit-learn / XGBoost / LightGBM，進階可用 LSTM 處理時序數據

### 產品三：自動化賽事分析報告（Newsletter / 訂閱服務）

**概念**：每場比賽結束後，自動抓取數據、執行分析、產出圖文並茂的深度報告。

**使用的數據**：全部

**報告內容範例**：
- 車手表現對比（圈速一致性、遙測差異）
- 輪胎策略復盤（誰的策略最成功、為什麼）
- 起跑得失位排行榜
- 安全車 / 天氣對比賽結果的影響分析

**商業模式**：
- 免費版：賽後摘要（社群媒體 / 部落格）
- 付費版：完整數據報告 + 獨家圖表（Substack / 自建平台）

**目標用戶**：F1 媒體、車隊低階分析人員、資深車迷社群

### 產品四：車手表現評分系統（Driver Rating Index）

**概念**：綜合多維指標，為每位車手每場比賽打出客觀評分，類似足球界的 WhoScored。

**使用的數據**：圈速一致性（CV）、超車數據、起跑表現、輪胎管理、排位 vs 正賽差距

**評分維度**：
| 維度 | 數據來源 | 說明 |
|------|---------|------|
| 單圈速度 | 排位賽最快圈 vs 隊友 | 純速度能力 |
| 比賽節奏 | 圈速標準差（CV） | 穩定性越高分越高 |
| 起跑能力 | GridPosition vs Lap1Position | 起跑得位越多分越高 |
| 輪胎管理 | 衰退率 vs 同胎種平均值 | 衰退越低分越高 |
| 超車能力 | 位置提升次數 | 正賽中超車越多分越高 |
| 抗壓表現 | 尾段圈速穩定度 | 比賽後段是否掉速 |

**輸出方式**：API（供媒體串接）、網頁排行榜、社群圖卡

### 產品五：Sim Racing 教練工具

**概念**：將真實 F1 遙測數據作為「標竿」，模擬賽車玩家上傳自己的遙測數據後，系統自動比對差異並給出改進建議。

**使用的數據**：遙測（Speed、Throttle、Brake、nGear vs Distance）

**功能**：
- 疊合真實車手與玩家的速度曲線，逐彎標示差異
- 自動偵測煞車點偏差（太早煞車 → 彎速不夠、太晚煞車 → 出彎速度慢）
- 油門運用分析（全油門百分比、出彎補油時機）
- 產出個人化練習建議

**目標用戶**：iRacing、Assetto Corsa、F1 遊戲社群

### 產品六：社群互動 Bot（Discord / Telegram）

**概念**：車迷在聊天群組中輸入指令，Bot 即時回傳分析圖表與數據摘要。

**使用的數據**：全部（依指令動態查詢）

**指令範例**：
| 指令 | 功能 |
|------|------|
| `/compare VER NOR monza 2024` | 回傳兩位車手的圈速對比圖 |
| `/strategy monza 2024` | 回傳全場輪胎策略時間軸 |
| `/standings 2024` | 回傳當前車手積分排行 |
| `/telemetry VER monza 2024` | 回傳遙測速度曲線圖 |
| `/weather bahrain 2024` | 回傳比賽天氣變化 |

**優勢**：低開發門檻（現有分析函數直接包裝）、高社群互動性、適合圈粉

### 產品七：F1 數據科學教學平台

**概念**：以 F1 數據為素材，製作 Python 數據分析與機器學習的教學課程。

**使用的數據**：全部（作為教學案例）

**課程模組範例**：
1. **Python 入門**：用 Pandas 讀取 laps.csv，做基本篩選與排序
2. **資料視覺化**：用 Matplotlib 畫圈速趨勢圖、輪胎策略圖
3. **統計分析**：計算輪胎衰退率（線性迴歸）、車手一致性（變異係數）
4. **機器學習**：用歷史數據預測比賽結果
5. **資料工程**：API 串接、自動化數據管線

**商業模式**：線上課程平台（Udemy / Hahow）、YouTube 系列影片

**優勢**：F1 是極具吸引力的教學主題，中文 F1 數據教學內容幾乎為零，市場缺口大

### 開發優先順序建議

| 優先級 | 產品 | 理由 |
|--------|------|------|
| 1 | 即時數據儀表板 | 現有模組完整度高，加 UI 層即可上線，最快看到成果 |
| 2 | 自動化賽事報告 | 分析流程已在 main.py 中串好，加文字模板即成報告 |
| 3 | 社群 Bot | 將現有函數包成指令，開發量小、社群效果好 |
| 4 | 車手評分系統 | 需要設計評分公式，但數據已齊全 |
| 5 | 賽事預測模型 | 需要累積更多歷史數據與特徵工程 |
| 6 | Sim Racing 教練 | 需要額外整合模擬器數據格式 |
| 7 | 教學平台 | 內容製作週期較長，但長期價值高 |
